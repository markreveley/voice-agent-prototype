9. **(agent)** Propose a policy rule, with its doctrine, for how agents change an existing doc, and ask Mark to approve the wording. Situation: some edits are awkward to make in place, such as rewriting table rows or adding links, so an agent may be tempted to write a fresh copy of the doc and trash the old one. Option A, edit in place: the doc keeps its ID, so every link to it keeps working, and its version history stays whole for rollback and checking. The cost is more, smaller edit steps, and a doc can be left half-updated if one step fails. Option B, replace with a new copy: one clean write, but the doc gets a new ID, every link to it breaks until fixed by hand, its version history starts over, and the trashed copy is easy to lose. Decision (Mark): always edit in place. If an in-place edit seems impossible, stop and ask Mark before replacing anything. Related decision (Mark): markdown docs don't use tables; use lists, one line per entry. A list line can be added with one insert or changed with one find-and-replace, while table cells in Google Docs need exact positions and are hard to edit in place. A table is easier to scan on screen, but Mark works by voice, where a list reads just as well. Pick the policy file it belongs in, and check that no skill replaces docs by uploading a new copy and trashing the old one.
